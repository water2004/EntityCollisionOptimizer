# 实体碰撞优化 (Entity Collision Optimizer)

Entity Collision Optimizer 是一个面向 Fabric 服务器的实体碰撞优化模组。它使用 Java FFM 原生空间索引处理实体推动候选，并使用稀疏方块索引处理实体移动与跨台阶的碰撞扫描。

模组接管服务端实体推动与移动碰撞，不接管或修改实体碰撞数量上限。最新迁移及其性能限制见 [native 移动与位置权威](docs/native-movement-position-2026-09-07.md)：对象分配减少，但本轮尚未得到端到端净提速。此前阶段见 [写入驱动位置记录](docs/write-driven-position-2026-09-07.md)、[查询优化记录](docs/native-query-2026-09-07.md) 和 [有序候选索引记录](docs/ordered-native-index-2026-09-07.md)。

## 支持范围

- Minecraft Java Edition **26.2**
- Fabric Loader **0.19.5 或更高的 0.19.x 版本**
- Fabric API **0.159.0+26.2 或更高的 26.2 兼容版本**
- Java **25**
- 仅支持 **Fabric**

模组可同时安装在客户端和服务端，优化逻辑只在服务端世界中执行。

## 运行模式

只保留两种显式模式，由配置项 `enableEntityCollision` 决定：

| 配置值 | 模式 | 行为 |
| --- | --- | --- |
| `false` | Vanilla | 不进入本模组碰撞路径，执行原版或已安装优化模组的逻辑 |
| `true` | FFM | 使用 FFM 原生碰撞后端 |

没有自动探测、后端选择参数或回退链。FFM 初始化或执行失败时会明确抛出错误，不会静默切换后端或跳过问题。运行 FFM 模式时建议添加 JVM 参数 `--enable-native-access=ALL-UNNAMED`。

## 原生平台

发布 JAR 的原生构建目标为：

- Windows x64
- Linux x64
- macOS x64

ARM64 暂不作为正式原生后端支持范围；在不受支持的平台上可将 `enableEntityCollision` 设为 `false` 使用 Vanilla 模式。

## 配置

首次启动后会生成：

```text
config/entity_collision_optimizer.json
```

默认配置：

```json
{
  "enableEntityCollision": true,
  "vanillaOrder": true,
  "gridSize": 1
}
```

`enableEntityCollision` 必须显式设为 `true`（FFM）或 `false`（Vanilla）。

`gridSize` 是原生 X/Y/Z 空间索引的格子边长，必须大于 `0`。实现始终返回所有相交候选，不包含候选上限、密度阈值、多线程开关或按密度分流的路径。

安装默认启用。使用 `/eco` 或 `/eco check` 查看状态；命令只开放原版顺序开关，修改后自动保存。命令需要游戏管理员权限。

`/eco vanillaOrder true` 开启原版实体推动候选顺序（默认）；
`/eco vanillaOrder false` 关闭排序专用维护，保留完整候选、去重、过滤与挤压计数。
此开关自动保存，下次重启生效；`check` 同时显示当前启动值和配置值。
无序启动不安装顺序记录注入，并加载编译时移除顺序字段、失效维护、排序及归并堆的 native 变体；运行期间不检查此开关。
关闭后不保证推动顺序、浮点累加及特殊实体回调与原版一致；不影响 Vanilla 后端，也不改变方块扫描顺序。

## 行为与兼容性

- 低密度和中密度场景以 Minecraft 26.2 原版行为为准。Fabric GameTest 对照候选顺序、位置、速度、接触标志、伤害及其他相关状态；覆盖范围和数值容差见 [兼容性与交互测试记录](docs/compatibility-parity-2026-09-07.md)。测试通过不等于穷举所有世界布局。
- 所有密度使用同一套原生空间索引和推动循环，不切换算法、不截断候选。可选中状态、队伍规则及其失效时机保持原版语义；原版派生队伍实时查询。native 空间单元缓存按原版 section 键及 section 内插入顺序排序的成员，只在成员或排序键变化时失效；查询有序合并并去重，返回全部候选和挤压计数，不再对每个来源的完整结果重新排序。先执行挤压伤害，再按候选顺序推动。高密度不作为行为一致性的保证范围。
- 普通实体推动按连续的原版行为分段执行 native 推动，包括普通僵尸继承的 `LivingEntity.push`。每个维度持有稳定实体槽位、每行 80 字节的共享状态表；绑定后的 XYZ 位置、速度及 `needsSync` 以该表为唯一权威。native 按原版顺序判定推动条件、计算冲量、逐次累加并处理有限值条件；位置/速度各有版本，Java 实际读取完整向量时生成并复用当前版本的 `Vec3`。没有逐段速度数组和段后 Java 发布循环；候选槽位在发布前完成绑定，不再逐目标准备位置。特殊推动或速度访问覆写仍按原版语义分派，不是密度分流或失败回退。
- `Entity` 的速度和位置全部读写、已审计的服务端 `needsSync` 读写及 `noPhysics` 写入，在全部 Mixin 注入和访问器生成后由同一转换器接入。位置在原来的字段写入点发布，构造和 `setPosRaw` 不依赖碰撞箱更新。消费者清单覆盖原版及已验证的 Carpet/VMP 对应代码，不包含客户端专用注入。可推动/载客/乘客/睡眠/穿墙及根载具身份按变化刷新到表中，由 native 判定每对实体的动作，不在 Java 逐对组装动作标志。原版脚下方块缓存清除时同步失效派生状态。未绑定实体使用原字段；解绑或关闭本模组时物化最新位置、速度与同步标志。反射、Unsafe、未纳入审计的字段消费者或之后追加访问的转换器不在兼容承诺内。
- 本模组启用时始终接管服务端 `LivingEntity.pushEntities`，忽略 Carpet 的 `maxEntityCollisions` 设置，不截断候选；原版 `maxEntityCramming` 挤压伤害规则保持生效。
- Lithium 可以同时安装。本模组启用时直接接管 `LivingEntity.pushEntities`，不进入 Lithium 对原版实体查询的注入；关闭本模组时，原版及已安装的 Lithium/Carpet 路径正常执行。
- 移动碰撞从 `Entity.collide`、两个 `collideBoundingBox` 及 `Entity.move` 的求解调用接管。native 用完整体素网格执行轴裁剪、台阶高度选择和目标位置计算，不执行 Lithium 对应的移动求解路径。Java 保留动态上下文形状收集及原版位置提交/世界回调顺序；重力、摩擦、碰撞后速度响应和方块效果还未全部迁入 native。不可变形状几何按对象缓存，查询只传有序引用和平移；原生缓冲按线程支持嵌套复用，不跨实体缓存上下文的形状选择。此功能同样由 `enableEntityCollision` 控制。
- 方块扫描按原版 z/y/x 顺序遍历，用非空气、大碰撞形状标志、运动中活塞三张位图，在读取方块状态之前执行原版扫描边缘筛选；通过筛选的方块仍实时查询原版形状。索引按需解码每行 16 个方块，附着在调色板上；单格写入同步更新三张位图，反序列化使其失效，复制容器独立建立索引。只缓存方块状态固有的筛选标志，不跨实体缓存碰撞形状，因此皮革靴、潜行、流体和活塞进度等上下文不会被冻结。没有按实体密度分流、速度限制或候选截断。验证与性能记录见 [方块边缘预筛选](docs/block-halo-prefilter-2026-09-07.md)。
- Worldthreader 可以同时安装。每个 `ServerLevel` 独立持有实体 ID、原生碰撞上下文、语义缓存、批次池和查询输出缓冲区；不同维度可以并行执行碰撞查询，不共享或串行化碰撞帧。三维度并发 GameTest 会交错执行 13,500 次原生查询和 4,500 次批量推动，检查跨维度实体、重复实体、计数及冲量缓冲区污染。
- 已联合加载验证 ServerCore、FerriteCore、C2ME、VMP、Krypton、Alternate Current、ScalableLux、Noisium、Lithium、Carpet 与 Worldthreader；该组合的全部 GameTest 通过。这里验证的是这些模组面向 Minecraft 26.2 的当前版本，不替未来版本提供无条件兼容承诺。
- 不为其他模组自定义的 `pushEntities` 或带副作用的 `isPushable` 实现提供额外兼容承诺。

## 构建

常规 Java/Fabric 编译可在 Windows、Linux 或 macOS 上执行，Gradle 会自动获取 Java 25 工具链：

```powershell
./gradlew.bat compileJava
```

包含全部原生库的发布 JAR 需要 Windows 10/11、MSVC 和 WSL：

```powershell
./gradlew.bat build
```

产物位于 `build/libs/`。

## 行为一致性测试

运行低密度和中密度的 Vanilla/FFM 差分 GameTest，以及跨维度并发隔离测试：

```powershell
./gradlew.bat runGameTest -Pparity
```

低密度测试包含 34 个分派情形，覆盖 26.2 中全部 `LivingEntity.doPush` 覆写类型及其主要分支：铁傀儡敌对目标/苦力怕排除/随机失败、Warden 的 no-AI/触碰冷却/出现姿态及愤怒和扰动记忆、鹦鹉与玩家、装备岩浆块后的硫磺立方体接触伤害、船的垂直接受/拒绝，以及蝙蝠和盔甲架的空覆写。目标侧还覆盖未载客马、可移动 Creaking、站立 Warden 和出现中的 Warden。其他分支包括 survival/creative/spectator 玩家、不可推动/死亡/攀爬/睡眠实体、`noPhysics`、乘客和同载具关系、队伍规则、普通挤压、全部精确重叠且推动无效果时的挤压、严格 AABB/section 边界、帧内移动与新增实体，以及同帧存活、攀爬、队伍、玩家旁观、Warden 姿态和马匹载客状态的 12 个双向切换。另有 4 个连续碰撞帧；中密度测试分别让 20 个全允许实体和 24 个混合队伍与状态的实体按原版顺序完成整轮推动，并逐实体对比速度、生命值和存活状态。并发测试为主世界、下界和末地建立不同大小的碰撞集合，并由三个线程同时验证空间查询、可推动计数和非乘客计数。

测试可以同时加载 Carpet 和 Lithium：

```powershell
./gradlew.bat runGameTest -Pparity -PcompatModsDir=<包含 Carpet 和 Lithium JAR 的目录>
```

普通僵尸用例额外断言 native 推动资格，防止测试仅覆盖 Java 路径。225 对冲量计算与原版 `Entity.push` 逐位比较（包含推力阈值与归一化分支边界）；另有 5 种速度观察、4 组 native 冲量连续累加序列、未经 getter 的真实速度字段读取、同帧睡眠—唤醒、嵌套批次隔离及查询后位置变化检查。历史优化记录见 [实体批量推动](docs/native-push-2026-09-07.md)，其延迟速度实现已被本轮修复替换。

推动段执行另有 90 组 2/8/20 实体用例，按 double 原始位比较完整段和拆分段在观察边界的速度、同步标志；覆盖负零、大数舍入、非有限原始速度的拒绝行为、睡眠、`noPhysics` 和收集候选后来源死亡。另在真实船推动回调入口观察 Java 速度字段，验证“普通段—特殊推动—普通段”的生效顺序。测试共注册 26 项（含原版 `always_pass` 和显式启用的压测入口），不是 26 组压力实验。

native 移动新增 6,114 个不同形状的 495,234 次逐位位移对照、75 次位置提交/世界回调状态观察，以及三线程 3,000 组嵌套事务和缓冲复用检查。位置共享行另验证读取权威、版本、扩容、转移和解绑。

共享状态另有 2/8/20 实体的 4 阶段真实服务端网络同步对照、22 次缓存后状态切换，以及未观察结果时的扩容/解绑/所有权迁移检查。有序索引另有 1,530 次真实原版候选列表对照和 8,640 次 native 查询检查，覆盖负 section 排序键、跨单元去重、元数据补齐、排序键独立变化、移出再进入、帧内新增/移除及网格重建。查询另有 2,160 组对照，使用原版 `SectionPos.posToSectionCoord` 检查六个 section 边界及相邻浮点值，并检查队伍规则、分派标志、元数据重试与固定偏移输出扩容。查询的来源边界只计算一次，ID、body slot 和分派标志在同一次遍历中填充。native 优化前的统一 CPU 归因见 [当前热点基线](docs/current-unified-hotspots-2026-09-07.md)。

方块碰撞另有 32,366 个已注册方块状态的有序形状对照、1,743 次移动/显式上下文差分、360 次运动中活塞形状及 halo 对照，以及 32 步连续移动的位置、速度、接触标志和落距检查。包含台阶、天花板、落地、轴顺序、微小位移、世界边界、流体、矿车上下文、皮革靴和潜行，以及 20 只僵尸与 4 艘船的中密度混合组；每次启用模式的移动差分还验证确实进入了本模组实现。调色板测试覆盖三种单格写入、复制隔离与反序列化。状态枚举不等于穷举所有世界布局或方块实体状态。

新增交互对照包括：72 组有方向的实体配对及 20 实体混合组、96 组地面/下落与冰/蓝冰/粘液/蜂蜜等表面、219 组活塞推动与蜂蜜携带、460 组异形方块移动、30 组流体/气泡柱、23 组机器通道/分流/卡边/蜂蜜滑落、12 组 TNT/两类风弹爆炸、8 组玩家击退 II 攻击和掉落物拾取，以及 10 组玩家实际投掷末影珍珠/风弹。点燃 TNT 同时作为可移动实体和爆炸来源测试。所有交互组比较关闭/开启本模组后的状态序列，不以“效果发生了”代替一致性。

## 碰撞基准测试

项目包含一个显式启用的 Fabric GameTest 基准：底部为石墙围成的 3×3 空间，中央上方有一块 1×1 石质垫脚方块，其顶面比底部地面高 5 格。每 tick 在垫脚方块上方同一个方块范围内生成 100 只默认 20 点生命、正常 AI 和重力的僵尸，出生点使用固定种子在 X/Z 各 ±0.18 格内分布，避免完全重合；靠正常移动和推挤离开平台并摔落；不施加额外下落或水平速度。连续生成并测量 200 tick，共生成 20,000 只，不预先堆怪或另加预热。死亡、挤压伤害、掉落物和经验球保持正常处理，测量结束后才清理场景残留。

一名无敌的生存模式服务端玩家站在底部，持击退 II 钻石剑，每 13 tick 尝试攻击底部可触及且可见的活僵尸。保留原版攻击速度和冷却，不清除僵尸受伤无敌帧；攻击执行原版伤害、击退和横扫。测试检查实际主目标伤害、水平击退，以及同一次攻击对其他僵尸造成的范围伤害，不把主目标命中当成横扫成功。

```powershell
./gradlew.bat runGameTest -Pbenchmark
```

默认只运行一轮启用优化的 200 tick 场景。环境变量 `ECO_BENCHMARK_PROFILE=baseline` 可改为关闭优化，`optimized` 为启用；两种模式需分别启动。普通 `build` 不会运行压测。`ECO_BENCHMARK_RESULT` 输出模式、生成总数、MSPT 和攻击/横扫统计；每 20 tick 的 `ECO_BENCHMARK_POPULATION` 输出当前存活、死亡中和已移除数量。出生和攻击组织开销计入计时，统计日志与最终清理不计入样本。存活数量随正常死亡变化，不再强制维持固定种群。

测试布局留出 96 格间距以隔离其他 GameTest 建筑。使用 `-PjfrOutput=<文件路径>` 保存 JFR，`ECO_MEASUREMENT_WINDOW` 标记完整的 200 tick 测量窗口。

设置 `ECO_SCAN_DIAGNOSTICS=true` 可按每 67 次僵尸移动采样一次请求/实际位移、扫描范围、方块读取量和步进分支，输出 `ECO_SCAN_RESULT` / `ECO_SCAN_PHASE`。这些统计和注入仅存在于 GameTest 模组；未设置该变量时不加载扫描注入，发布 JAR 不包含诊断代码。统计中的 `state_reads` 是候选扫描读取，不包含首次建立位图的读取，也不包含 Lithium 自己的扫描器。带统计的 MSPT 不应用作正式性能对照。

本次接管的测量、限制和复现说明见 [移动碰撞优化记录](docs/movement-collision-2026-09-07.md)。
