本模组 DLL 内：候选排序 **5,795 / 13.37%**，查询主体 **3,874 / 8.94%**，推动段计算 **2,956 / 6.82%**，其余 **47 / 0.11%**。这些均使用全线程分母。

本模组包名下的 Java 编译代码共 **12,606** 个样本，与 DLL 的 **12,672** 个相加为 **25,278 / 58.32%**，没有重复计算。它不是完整碰撞 CPU 占比的精确值；它已足以否定“碰撞不再重要”。优化关注点应包括整个推动链的数据准备、Java 状态写回和重复排序，而不仅是 native 算术或小范围方块位图计算。本次只诊断，尚未实现新的生产优化。
