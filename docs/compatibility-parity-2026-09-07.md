# 兼容性修复与交互差分测试（2026-09-07）

## 判定标准

目标是原版实体/方块在低密度和中密度下的行为一致性，不是只验证推动、弹跳或传送确实发生。所有密度使用相同实现，没有密度阈值、候选截断、`maxcollision` 或 native 失败回退。本轮没有实现高密度近似聚合，也没有给高密度行为作额外保证。

新增交互用例在相同坐标分别建立独立的关闭/开启实例，比较每一步的位置、速度、接触标志、落距、生命值、掉落物数量、着火/冻结状态、移除状态和点燃 TNT 引信；玩家投掷另外比较物品消耗和冷却。向量差的平方不超过 `1e-24`，即距离误差不超过 `1e-12`；落距容差 `1e-12`，离散状态与生命值精确相等。225 对 native 冲量及 4 组连续累加另按 double 原始位比较。

每个模式执行真正的 Minecraft 方法作为被测行为，没有用第二份推力公式充当原版预期值。未安装优化模组时关闭模式就是原版；安装优化模组时关闭模式保留这些模组，因此另外验证该运行环境下关闭/开启的一致性。

测试中的“必须确实弹跳/传送/产生爆炸推力/穿过出口”只是辅助防空测断言。验收条件仍是两种模式的完整被观察状态序列一致。

## 找到并修复的三个契约问题

三项回归在旧实现的 `eco-contract-before-20260907.log` 中均实际失败，修复后纯 Fabric 和优化模组组合均通过。

| 问题 | 复现 | 修复 |
| --- | --- | --- |
| 派生队伍未随状态改变 | 狼从野生变为驯服、指定/取消主人、取消驯服，期间不修改记分板 | 只有直接使用 `Entity.getTeam` 的查询保留记分板缓存；派生队伍实时读取并在查询前刷新 native 元数据 |
| native 候选顺序不是原版顺序 | 跨空间格/section 的交错插入、移走、返回；旧测试只比较集合而未检查顺序 | 观察实际 `EntitySection.add` 顺序，native 按原版 section 键顺序及 section 内插入序号排序 |
| 延迟速度保留第二份可观察状态 | native 推动后不调用 getter，直接读取实体真实 `deltaMovement` 字段 | 删除延迟冲量接口与 Mixin，按原版次序调用向量推动，立即更新真实字段 |

最后一项也避免 Carpet 等直接读取速度字段的消费者看到旧值。修复没有修改 Carpet 的碰撞数量规则：其启用数量限制时仍由 Carpet 完整管理实体推动。

## 注入与维护边界

- 生产配置从 14 个 Mixin / 29 个 `@Inject` 声明 / 4 个 invoker，减少为 **13 个 Mixin / 28 个 `@Inject` 声明 / 2 个 invoker**。计数是声明数，多目标注入可能对应多个方法。
- 可取消的接管入口仍是四处：`LivingEntity.pushEntities`、`Entity.collide`、两个 `collideBoundingBox` 重载。其余主要观察状态变更或维护方块/实体索引；不是每类交互各补一个注入。
- 新增一个 section 插入观察，删除整个延迟速度 Mixin。两个只供测试使用的 invoker 移至 GameTest source set；新增玩家/风弹/字段访问器也只存在于测试模组。
- Lithium 的推动和移动求解入口仍由本模组统一接管，不为楼梯、蜂蜜、珍珠等各写一份兼容补丁；不冲突的底层形状优化继续工作。
- 每维度数据从全局入口类拆到 `LevelCollisionFrame`，继续维持维度独立上下文、缓存、批次池和缓冲区。测试按表面、流体、机器、投射物、玩家等职责分文件，未重新集中进巨大 `CollisionParity.java`。
- `getDeclaredMethod` 只用于判断继承/覆写所属类，不能识别其他模组向现有方法体注入的任意语义。这里只承诺已测试的原版和指定优化模组环境，不宣称可兼容所有自定义实体或带副作用的自定义谓词。

## 夹具修正与测试局限

扩大测试过程中先修正了几种会掩盖行为或制造伪差异的夹具问题，没有为这些问题改生产碰撞算法或放宽容差：

1. GameTest 建筑间距可能把测试区域放在地形下面；现在显式建立整块空气空间，避免所谓“无遮挡爆炸”实际上被地下石头遮挡。
2. GameTest 自带模拟玩家是强制返回创造模式的子类。现在使用真正 `ServerPlayer`、生存模式和正常加载完成事件，并恢复相关生存伤害规则。否则珍珠伤害和玩家碰撞测试会测错对象。
3. 直接调用 tick 时补上服务器通常在外层进行的旧坐标保存及 `tickCount` 递增。否则末影珍珠会使用未初始化的旧坐标。
4. 掉落物低速移动按 `(tickCount + id) % 4` 错峰。配对夹具在注册前赋相同的未使用 ID，使两次运行的阶段一致；不篡改已注册实体的索引。
5. 硫磺立方体的身体初始化可能推动附近实体；初始化在远处完成，场景组装后再次统一初始速度、随机种子和同步标志，并比较初始快照。

这些是受控物理步骤的差分测试，不是所有机器都在完整世界 tick 下连续运行的端到端仿真：活塞测试直接 tick 真实运动方块实体，分流测试输入相同位移，爆炸测试比较命中后若干步；不覆盖完整红石时序或所有跨 tick 联动。玩家投掷通过真实物品使用创建投射物，但归一化初始散布速度以隔离随机差异，不检验随机散布分布。没有穷举所有实体组合、所有朝向/方块实体数据、跨维度珍珠或所有游戏规则。

## 性能代价

同一 1,000 正常僵尸石室、生存玩家击退 II 场景，完整优化组合，单模式 120 tick 预热 / 600 tick 测量：新实现 **62.717 MSPT**，中位数 61.454，p95 70.734，55 次攻击中 11 次接受且均有击退。未开启 WPR 或方块扫描统计，开启 JFR。

历史实现 `c7c5185` 单模式为 47.113 MSPT；新版这次观察慢约 33.1%。这是不同进程、独立自然种群的观察，不足以把差额分别归因于排序或即时速度写入。不能把旧版的性能数字继续当作新版表现，也不以删除一致性修复换回旧数字。

另运行一次 ABBA（关闭/开启/开启/关闭，每轮重建种群、80 tick 预热 / 200 tick 测量），保留所有优化模组：

| 轮次 | 模式 | 平均 MSPT |
| --- | --- | ---: |
| 0 | 关闭 | 196.057 |
| 1 | 开启 | 59.514 |
| 2 | 开启 | 64.499 |
| 3 | 关闭 | 184.725 |
| 合并 | 关闭 / 开启 | **190.391 / 62.007** |

本次整体下降 **67.43%**，不是本轮修改相对上一版的独立收益；只运行一组 ABBA，不作为跨机器或多次重复实验的统计结论。机器同时进行过旧 JFR 的解析，宿主负载并非完全隔离。84 次攻击中 16 次接受且均有击退。

单模式 JFR 只取测量窗口 `1788721350746..1788721388462` 和 `worldthreader_minecraft:overworld` 线程。1,755 个 Java 执行样本的主要叶子：

| Java 叶子方法 | 样本 | 占 Java 执行样本 |
| --- | ---: | ---: |
| `Entity.push` | 394 | 22.45% |
| `PalettedContainer.get` | 275 | 15.67% |
| `LevelCollisionFrame.collectPushable` | 245 | 13.96% |
| 实体可推动性缓存读取 | 96 | 5.47% |
| `PushBatch.applyNativeRun` | 88 | 5.01% |

按完整调用栈中最近的本模组方法归属，`PushBatch.apply` 为 531 个（30.26%），有序方块扫描 `Scan.run` 为 301 个（17.15%），候选快照 `collectPushable` 为 245 个（13.96%）。逐对速度写入、候选收集与方块扫描仍是 Java 侧重点；这是采样归属，不是精确方法耗时。

同窗口另有 410 个 `NativeMethodSample`：371 个经 `FFMBackend.queryPushable`、33 个经 `calculatePushImpulses`、5 个分配外部内存、1 个建帧。说明 native 查询明确被采到，但不能据此分离排序耗时。Java 样本与 native 状态样本不能相加作为 CPU 百分比；旧版 WPR 的 13.08% native CPU 结论只适用于旧版那次录制。本轮没有重新采集 WPR，因此不报告新版 native CPU 占比。
